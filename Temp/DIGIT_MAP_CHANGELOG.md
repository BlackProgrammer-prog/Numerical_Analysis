# Digit Map Integration – Change Notes

هدف این تغییر، جدا کردن مجموعهٔ رقم‌ها از کد الگوریتم‌هاست تا در آینده با ویرایش `digit_map.json` بتوان کاراکترهای جدید اضافه کرد.

## فایل‌های داخل `Temp`

### `digit_map.json` — فایل جدید
- نگاشت مقدار هر رقم به کاراکتر نمایشی را نگه می‌دارد؛ کلید، مقدار عددی رقم و مقدار، کاراکتر آن است.
- نگاشت فعلی از `0` تا `61` پیوسته است: ارقام `0–9`، حروف بزرگ `A–Z` و حروف کوچک `a–z`.
- بنابراین الفبای فعلی ۶۲ کاراکتر دارد و حداکثر مبنای قابل پشتیبانی در لایهٔ الگوریتم‌ها ۶۲ است.

### `conversion_validation.py` — اصلاح‌شده
- فایل JSON را با UTF-8 از کنار خودش بارگذاری می‌کند.
- نگاشت را بررسی می‌کند: کلیدها باید از صفر و بدون فاصله ادامه‌دار باشند؛ کاراکترها باید تک‌کاراکتری، یکتا و غیررزروشده باشند.
- از روی JSON، `DIGITS`، `DIGIT_TO_VALUE` و `MAX_BASE` را می‌سازد؛ بنابراین سقف مبنا مستقیماً از تعداد کاراکترهای JSON به دست می‌آید.
- اعتبارسنجی مبنا و رقم ورودی را بر اساس نگاشت انجام می‌دهد.
- برای حفظ رفتار قبلی، در مبناهای ۲ تا ۳۶ حروف ورودی را به uppercase تبدیل می‌کند؛ از مبنای ۳۷ به بالا حروف بزرگ و کوچک مستقل هستند.

### `Alireza_mabna10.py` — اصلاح‌شده
- به‌جای الفبای ثابت، `DIGITS` و `DIGIT_TO_VALUE` را از `conversion_validation.py` دریافت می‌کند.
- تبدیل کاراکتر به مقدار و تولید رقم خروجی را با نگاشت JSON انجام می‌دهد.
- منطق ریاضی روش استاندارد (محاسبهٔ دقیق با `Fraction`) تغییر اساسی نکرده است.

### `Meysam_horner.py` — اصلاح‌شده
- همان نگاشت مشترک را از `conversion_validation.py` دریافت می‌کند.
- خواندن رقم‌های ورودی و ساخت خروجی روش Horner با الفبای JSON انجام می‌شود.
- متغیر `digits` برای سازگاری با بخش‌های موجود، به `DIGITS` مشترک متصل شده است؛ منطق اصلی محاسبهٔ Horner تغییر اساسی نکرده است.

## نکات ادغام با بک‌اند

1. چهار فایل بالا باید در زمان ادغام کنار فایل‌های اصلی پایتون پروژه قرار بگیرند؛ به‌خصوص `digit_map.json` باید در همان پوشه‌ای باشد که `conversion_validation.py` قرار دارد، چون مسیر JSON نسبت به محل همین فایل ساخته می‌شود.
2. JSON هنگام import شدن `conversion_validation.py` بارگذاری می‌شود. پس از تغییر JSON، برنامهٔ بک‌اند باید مجدداً راه‌اندازی شود تا نگاشت جدید بارگذاری شود.
3. در `backend/main.py` هنوز محدودیت‌های API روی مبنای ۳۶ هستند (`sourceBase` و `targetBase` و توضیحات مربوط به بازهٔ مبنا). برای فعال شدن مبناهای ۳۷ تا ۶۲ در API، این محدودیت‌ها و تست‌های API باید جداگانه به ۶۲ به‌روزرسانی شوند.
4. فرانت‌اند در این تغییر دست‌نخورده است و برای نمایش/انتخاب مبناهای جدید باید جداگانه به‌روزرسانی شود.
5. برای افزودن کاراکترهای بعدی، کلیدهای عددی پیوسته بعد از `61` اضافه شوند. هر کاراکتر باید یکتا و دقیقاً یک Unicode character باشد؛ از فاصله، `+`، `-` و `.` استفاده نشود.

**محدودهٔ این تغییر:** فقط دو الگوریتم و لایهٔ اعتبارسنجی آن‌ها به JSON متصل شده‌اند؛ `backend/main.py`، فرانت‌اند و فایل‌های اصلی پروژه در این بسته تغییر داده نشده‌اند.
